Explanation of transitive versions:
  - Spring AI BOM 2.0.1 only adds version constraints for the artifacts it
    manages (notably Jackson 3.x databind/core via tools.jackson). It does NOT
    pin Spring Framework, so the Boot 4.1.1 BOM keeps Spring Framework at 7.0.9
    everywhere. The (c) lines are BOM constraints, not duplicate versions.
  - Jackson 3.x splits the group: databind/core moved to tools.jackson while the
    2.x com.fasterxml.jackson annotations are retained for binary compatibility.
    The BOM-managed ObjectMapper serializes/deserializes correctly at runtime
    (see SpringAiBomCompatibilityTest).

Known follow-up (out of scope for S01-08):
  - No JavaTimeModule (jsr310) is on the runtime classpath, so LocalDate /
    LocalDateTime do not round-trip through the Boot-configured ObjectMapper.
    This is a Jackson 3.x ecosystem question (module availability / Boot
    autoconfiguration), not a Spring BOM incompatibility. Resolve before persisting
    or serializing 8-time values; likely needs an explicit jackson-jsr310-style
    module for Jackson 3.x, or a registered JavaTimeModule. Do not add without
    verifying the Jackson 3.x module exists and is Boot-detectable.
