## Unreleased

### Added
- **The storage config and object-key convention (S10-02): a typed, validated `agentflow.storage.*` group (`AgentFlowProperties.Storage`) and the server-generated, tenant-scoped object-key convention `documents/<tenantId>/<documentId>[.<ext>]` (`com.example.agentflow.knowledgebase.domain.DocumentObjectKey`).** The `Storage` group binds `bucket` (default `agentflow`, matching the Garage bucket in `infra/compose`), `region` (default `garage`), `public-access` (`disabled` by default — the bucket is private; an object is never addressable through a public or anonymous URL) and `endpoint` (environment-specific; supplied per profile by the S3 client in `S10-03`, and a `null` endpoint fails clearly when the client is built, never silently). The `endpoint` / bucket / region come from the git-ignored local `.env` (`AGENTFLOW_OBJECT_STORAGE_*`); the S3 credentials (`AGENTFLOW_OBJECT_STORAGE_ACCESS_KEY` / `AGENTFLOW_OBJECT_STORAGE_SECRET_KEY`) come from the environment only, never from configuration or source (invariant 8). The object key is generated <b>server-side</b> from the server-issued identifiers — never from the client `filename`, and never a path the filename controls — so a hostile or prompt-injected `filename` can never become an object path or leak across tenants (invariant 1 / the S10-04 key-generation acceptance); the only separators are the fixed `documents/` prefix plus the two server UUIDs, and an extension (when present) is a content-type hint only, validated against a closed whitelist and never a path segment. The `Storage` group mirrors `AgentFlowProperties` with the same `@Validated` + `@ConfigurationProperties` binding, `@Valid` on the nested group and `@Autowired(required = false)`-style defensiveness. The acceptance is pinned by two DB-free suites (14 tests): [`DocumentObjectKeyTest`](apps/agentflow-app/src/test/java/com/example/agentflow/knowledgebase/domain/DocumentObjectKeyTest.java) — the key is generated from the ids, never the filename, the exact canonical shape (no extra segment, no `..`, no extension that is a path), extension is a content-type hint only, immutability and rejection of a hostile key — and [`StoragePropertiesTest`](apps/agentflow-app/src/test/java/com/example/agentflow/StoragePropertiesTest.java) — the safe defaults bind, the bucket is private by default (no public URL), custom `endpoint` / `bucket` / `region` bind, `public-access` is reachable only by explicit opt-in and an invalid value fails startup through the validated binding. DB-free (no `DataSource` / S3 dependency); the module boundary is unchanged — `knowledgebase` still compiles only against `ai` / `workflowexecution`, and the pure `DocumentObjectKey` imports only `java.util.*`. `:apps:agentflow-app:check` green — [detailed](docs/devlog/sprint-10-document-ingestion.md)
- **The document lifecycle (S10-01): [`docs/architecture/document-lifecycle.md`](docs/architecture/document-lifecycle.md)** — the `documents.status` state machine of `knowledgebase`, as a diagram and a guarded transition table (the document-layer mirror of the run state machine, `S05-01`). The lifecycle is `UPLOADED → QUEUED → PROCESSING → INDEXED`, with `FAILED`, `DELETE_REQUESTED`, `DELETED`: `UPLOADED` (object stored + metadata row committed; the upload API returns `202`), `QUEUED` (the `ingestion-requested` event is enqueued via the outbox, awaiting a worker), `PROCESSING` (an `ingestion` worker holds the lease and is extracting → chunking → embedding → indexing), `INDEXED` (all chunks indexed — pgvector + FTS), `FAILED` (permanent failure or an exhausted retry budget), `DELETE_REQUESTED` (deletion requested; the lease is drained) and `DELETED` (object + chunks removed). Three terminal states — `INDEXED`/`FAILED`/`DELETED` — are absorbing; the only backward edge is `PROCESSING → QUEUED`, the bounded **retry** (a transient re-queue, at-least-once and idempotent by `tenant_id + sha256 + pipeline_version`, so a redelivered event never duplicates chunks); `PROCESSING → FAILED` fires on a permanent failure or a retry budget exhausted. A delete command (`DELETE /api/v1/documents/{documentId}`) moves any non-terminal / `FAILED` document through a two-phase, one-way `DELETE_REQUESTED → DELETED` (the run's `CANCEL_REQUESTED → CANCELLED` mirror), draining a `PROCESSING` lease cooperatively without overwriting a completed result. Every transition goes through the single `knowledgebase` transition service — a conditional update + optimistic `version` + append-only audit record in one transaction — never set directly from a controller or listener; the `ingestion` worker leases + indexes + publishes `document.indexed` (`status = INDEXED`), but `knowledgebase` owns and applies the status. This is a **documentation-only** change (`S10-01`): the enum, the transition service and the upload/delete API are implemented by `S10-03` … `S10-13` and are not on disk yet, so there is no `:apps:agentflow-app:check` gate for this task — the acceptance ("every transition explicitly described and verified") is met by link integrity + `git diff --check` and the glossary / events cross-check, and the diagram matches the state set already fixed in [`docs/domain-glossary.md`](docs/domain-glossary.md) §7. — [detailed](docs/devlog/sprint-10-document-ingestion.md)

- **The model budget guard (S09-10): a model call is never sent against an exhausted budget — the per-call estimate is reserved *before* the call and a reservation that would exceed the limit is refused, so an over-budget plan fails loud at call time and never burns the model.** The S09-08 bounded repair re-checks the budget *before every retry*; S09-10 makes that check a real, pre-call reserve-with-the-funds guard rather than a `Supplier<Boolean>` predicate, mirroring how the provider port uses the same opt-in, loud-at-call-time seam. Three pure value types in `com.example.agentflow.ai.application` — [`ModelBudget`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/ModelBudget.java) (the in-memory reserve/settle/validate guard with the committed `reserved` headroom), [`ModelBudgetReservation`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/ModelBudgetReservation.java) (the reconciliation handle returned by a `reserve`), and [`InsufficientBudgetException`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/InsufficientBudgetException.java) (carries the `available` / `limit` / `currency`, thrown *before* the request is sent) — are the `ai`-module mirror of `usage`'s durable budget. **Ownership:** the durable data lives in `usage` (the limits in `tenant_budgets`, the metering in `usage_records`, the price catalogue); a compile edge `ai → usage` is forbidden by the boundary gate, so — exactly as `ai` owns its own [`ProviderResiliencePolicy`](CHANGELOG.md) for bounded retry — this task owns only the pre-call guard in `ai.application`, and the full at-least-once settlement-reconciliation (deduplicated by record id) is `S12`. **Semantics:** `reserve()` reserves a conservative (upper-bound) estimate and throws `InsufficientBudgetException` when the reservation would exceed the `limit` (an over-budget refusal that is permanent and never retried, invariant 12); `settle(actual)` reconciles the reservation *without ever accumulating* (`reserved = reserved − estimated + actual`, floored at 0), so a reservation is committed at most once and `settle(null)` (the price catalogue is not yet metered) leaves it unchanged — idempotent, not a leak. The guard is opt-in: `PlannerService` depends on `@Autowired(required = false) ModelBudget budget`, so a missing bean is "no budget guard" and the Planner still runs standalone; a shared production bean makes the reservation the running commitment. [`PlannerService.propose`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/PlannerService.java) now reserves before the attempt and settles after the model reports back. Two DB-free unit suites (23 tests, JUnit XML checked, all green): [`ModelBudgetTest`](apps/agentflow-app/src/test/java/com/example/agentflow/ai/application/ModelBudgetTest.java) (10 — reserve against limit blocks, available is `limit − reserved`, settle reconciles rather than accumulates, `settle(null)` is a committed no-op, settlement is idempotent) and [`PlannerServiceTest`](apps/agentflow-app/src/test/java/com/example/agentflow/ai/application/PlannerServiceTest.java) (13 — the budget seam is now a `ModelBudget`, with the three S09-10 acceptance paths: reserve-before-call blocks an exhausted budget, a settled call releases the reservation, and the guard is evaluated before the S09-08 repair retry too). The previously obsolete S09-08 budget test (`propose_does_not_retry_when_budget_is_unavailable`) is replaced by the three S09-10 paths. The `ai` module boundary is unchanged — `ai` still compiles only against `ai`, `toolexecution` and `workflowexecution` (the `ArchitectureBoundaryTest` / `PackageDependencyGraphTest` gates stay green); the exception's `ErrorClass` mapping is added when the planner is integrated into the step / HTTP path, because `workflowexecution` reaches `ai` only through the runtime `StepHandler` SPI (never a compile edge), so the owning `ai` module maps its own domain exception. Metrics and logs carry no budget figure in a label and no id (invariant 9); monetary amounts travel only in the exception, never in telemetry. `:apps:agentflow-app:check` green — [detailed](docs/devlog/sprint-09-ai-planner.md)
- **Provider resilience (S09-09): a model call is bounded — a finite number of attempts, an upper bound on the total wait, a per-attempt wall-clock timeout and a parallel-call cap — and only transient faults (429 / 5xx / timeout / connection) are retried.** [`ProviderResiliencePolicy`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/ProviderResiliencePolicy.java) (`ai.application`) is the `ai` module's own bounded-retry descriptor — `maxAttempts`, `baseDelay`, `multiplier`, `maxDelay`, full jitter — a pure value object with canonical-constructor validation and injected time/randomness seams (invariant 10), mirroring the `workflowexecution` / `toolexecution` retry-policy shape without importing them (the boundary gate forbids it). [`ProviderFailureReason`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/ProviderFailureReason.java) is the neutral, SDK-free classification (`RATE_LIMIT` / `SERVER_ERROR` / `TIMEOUT` / `CONNECTION` retryable; `CLIENT_ERROR` / `UNKNOWN` permanent); the SDK-specific mapping lives only in [`ProviderExceptionClassifier`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/provider/ProviderExceptionClassifier.java) (`ai.provider`, the only code that understands the OpenAI exception hierarchy — it walks the whole cause chain and matches the specific 429/5xx types before the generic status-code branch). [`ResilientChatModel`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/provider/ResilientChatModel.java) wraps any `ChatModelPort` with the three independent bounds: bounded exponential backoff + full jitter only while the policy allows another attempt and the fault is retryable; a per-attempt overall timeout enforced on a daemon executor (an abort is classified as `TIMEOUT` and retried within the same bound); and a `Semaphore` concurrency cap that rejects overload immediately with a retryable `ProviderConcurrencyLimitedException` backpressure signal. [`OpenAiChatModelConfiguration`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/provider/OpenAiChatModelConfiguration.java) now wires the connect/read timeouts into the underlying SDK client (from `agentflow.ai.timeout.*`) and exposes the resilient wrapper as the `@Primary` `ChatModelPort`, so the domain sees only the port — never a timeout, an SDK type, or the raw adapter; all bounds live in configuration (`agentflow.ai.retry.*`, `agentflow.ai.max-parallel-calls`), never hard-coded. An external call stays not-exactly-once (invariant 6): the wrapper only makes a failed call fail cleanly and in bounded time. Four suites (39 tests, JUnit XML checked, all green) pin the acceptance — `ProviderResiliencePolicyTest` (bounded backoff, cap, `maxTotalBackoffMillis` upper bound, validation), `ProviderExceptionClassifierTest` (every SDK fault class → reason, cause-chain walk), `ResilientChatModelTest` (finite attempts never infinite, total wait ≤ the policy bound, overall-timeout abort across finite retries, concurrency-cap throttle) and `OpenAiChatModelConfigurationTest` (the port is the resilient wrapper delegating to the OpenAI adapter). `:apps:agentflow-app:check` green — [detailed](docs/devlog/sprint-09-ai-planner.md)
- **The bounded repair of a malformed plan (S09-08): an untrusted-planner response that is not a valid plan is classified, and a repairable failure is repaired with at most one corrective retry — only when the budget allows and only for a repairable failure — so a malformed output never drives an infinite loop of model calls.** The four ways a model attempt can fail are distinguished by [`PlannerFailure`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/PlannerFailure.java) — `MALFORMED_JSON`, `SCHEMA_MISMATCH`, `PROVIDER_REFUSAL`, `TRANSPORT_FAILURE` — with `isRepairable()` marking the three the retry can fix (`MALFORMED_JSON` / `SCHEMA_MISMATCH` / `TRANSPORT_FAILURE`) and never the refusal (retrying a refusal only burns the budget). [`PlannerRepairPolicy`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/PlannerRepairPolicy.java) (`com.example.agentflow.ai.application`) is the bounded descriptor (`of(int)` with canonical-constructor validation rejecting `maxRetries < 0`; `ofDefaults() == 1` — the production single-second-chance); it is a pure value object with value equality. The S09-06 signal [`PlannerPlanParseException`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/PlannerPlanParseException.java) now carries that classification (`classification()`), so the caller can tell a provider formatting fault apart from a structural violation or a refusal. The [`PlannerService.propose`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/PlannerService.java) contract method now runs the model at least once, and — only for a repairable failure, only while `budget.get()` permits, and at most `repairPolicy.maxRetries()` times — calls it again, then lets the last allowed retry's failure be terminal, so a malformed plan is a clear, visible fault, never a silent `null` plan and never an infinite model-call loop (the S09-08 acceptance). The budget gate is the same opt-in, loud-at-call-time seam the provider port uses (an injected `Supplier<Boolean>`); the retry is evaluated *before every retry*, so a budget consumed by the initial call blocks it. The `ai` module boundary is unchanged — `ai` still compiles only against `ai` — and the transport-failure classification is the only new behavior added to the port boundary. Three DB-free unit suites (17 tests, JUnit XML checked, all green): `PlannerFailureTest` (the four classifications and their repair decisions), `PlannerRepairPolicyTest` (the policy contract and its validation), and `PlannerServiceTest` (11 — repair once after a malformed / schema-mismatch / transport failure, give up after one retry on persistent malformed output, never retry a refusal, never retry without budget). `:apps:agentflow-app:check` green — [detailed](docs/devlog/sprint-09-ai-planner.md)
- **The validation gate (S09-07): the model *proposes*, the backend *authorizes before executing* — an unknown tool, a dependency cycle or an over-limit plan is rejected server-side and never reaches the executor.** [`AiPlanExecutionService`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/AiPlanExecutionService.java) (`ai.application`) is the S09-07 entry point: it runs a [`ValidationGate`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/ValidationGate.java) *before* a single step reaches the executor, then hands the validated plan to the optional [`PlanExecutor`](apps/agentflow-app/src/main/java/com/example/agentflow/ai/application/PlanExecutor.java) port.
