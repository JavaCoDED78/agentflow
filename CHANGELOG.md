- **Trace context over Kafka (S13-10): the producer and consumer legs of the outbox/inbox boundary now carry the W3C trace-context header end to end, and each leg creates its own span parented on whatever the headers say — the queueing delay between PostgreSQL and the worker is no longer a trace break.** New [`MessagingTracing`](apps/agentflow-app/src/main/java/com/example/agentflow/messaging/application/MessagingTracing.java) (the single trace-context builder for the `messaging` boundary: `parentContext`, `startSpan`, `currentTraceparent` — correlation/causation ids recorded as attributes, never tenant/run/document ids). [`KafkaMessageDeliverer`](apps/agentflow-app/src/main/java/com/example/agentflow/messaging/worker/KafkaMessageDeliverer.java) (producer) derives its trace parent and span attributes from that record `traceparent` and now exports a `KafkaMessageDeliverer#deliver` span parented on the API request span — bracketing the blocking `send().get()`, closed on permanent auth failure; a corrupt or blank header set is detected and logged, never silently overwritten. [`DocumentIndexingWorker`](apps/agentflow-app/src/main/java/com/example/agentflow/ingestion/worker/DocumentIndexingWorker.java) (consumer) runs each `handle()` inside a `DocumentIndexingWorker#handle` span parented on the record's `traceparent` header — correlation/causation from the headers recorded as attributes, span closed in a `finally`. [`CorrelationHeaders`](apps/agentflow-app/src/main/java/com/example/agentflow/messaging/application/CorrelationHeaders.java) / [`OutboxService`](apps/agentflow-app/src/main/java/com/example/agentflow/messaging/application/OutboxService.java) (the outbox boundary) — `OutboxService#enqueue` threads the active span's `traceparent` into an event built from a traced context when the producer did not set one (`CorrelationHeaders` gains `parse(...)`, the reader of the producer-written `headers` JSON): an explicit `traceparent` always wins; a corrupt payload is left untouched; a blank payload still yields the threaded `traceparent`. [`OutboxEvent`](apps/agentflow-app/src/main/java/com/example/agentflow/messaging/domain/OutboxEvent.java) gains `withHeadersJson` (the record already carried the raw `headersJson`; no new schema, no migration — the `headers` JSON shape is unchanged). **Tests.** `MessagingTracingTest` (10), `RecordingSpanExporter` (the `SpanExporter` test double), `OutboxServiceTest` (5 — threaded / explicit-wins / blank / unchanged / corrupt), `DocumentIndexingWorkerTest` (8 — 2 new span cases; JUnit XML fresh, `failures=0`, `errors=0`, `skipped=0`), `KafkaTraceContextIT` (1 — the real-broker end-to-end trace-context IT), `spotlessApply` applied. **Docs.** `docs/architecture/kafka-topics.md` (the trace-context propagation subsection); `docs/architecture/module-api.md` (`messaging` / `observability` rows — `MessagingTracing` + the trace-context builder's home); `docs/architecture/module-map.md` (cross-cutting packages — the builder's home); `docs/domain-glossary.md` (correlation headers — the append path threads `traceparent`, not the single producer); `docs/observability/standards.md` (the real messaging spans in the naming examples); `apps/agentflow-app/src/main/java/com/example/agentflow/observability/AGENTS.md` (where the trace-context builder lives); [`docs/devlog/sprint-13-observability.md`](docs/devlog/sprint-13-observability.md) (new S13-10 section + contents line); `CHANGELOG.md` (this entry). — [detailed](docs/devlog/sprint-13-observability.md#s13-10-trace-context-over-kafka)
- **Standardized JSON logs (S13-09): the log line is now a single, pinned contract — a dedicated encoder owns the shape, exactly five MDC keys are written inline, and a per-request correlation id appears in every log line and in the response header.** The new [`StructuredJsonLogstashEncoder`](apps/agentflow-app/src/main/java/com/example/agentflow/observability/StructuredJsonLogstashEncoder.java) extends the logback logstash encoder with exactly the pinned shape: `@timestamp`, `severity` (not `level`; the numeric `level_value` dropped), `message`, `logger_name`, `thread_name` and `exception` — with the MDC written **inline, whitelisted** to `service` / `environment` / `traceId` / `spanId` / `correlationId` — so a stray high-cardinality id (tenant/run/user/document) that any caller puts into the MDC never reaches a log line. The new `CorrelationIdFilter` (`observability`, `OncePerRequestFilter`) seeds `correlationId` for the duration of one HTTP request — the active `traceId` when tracing is wired (so the log line and the trace id agree), a fresh UUID otherwise — and removes it in a `finally` block even when the chain throws, so it never leaks into unrelated requests on a thread pool. `GlobalExceptionHandler` reads the filter-seeded `correlationId` first (then `traceId`, then a fresh UUID), so the response's `correlation_id` is the same id that appears in every log line of the request. `logback-spring.xml` now points at the dedicated encoder — the single place the JSON log field contract lives; masking stays on the wire path (`MaskingJsonGeneratorDecorator` + `SecretRedactingValueMasker`, ADR-020), so bearer/JWT/api-key/AWS-key/prompt/document-body shapes never reach stdout or Loki. **Tests.** `LoggingJsonFormatTest` (2 — the structured fields + exactly the whitelisted MDC keys inline with stray tenant/run/user ids dropped + canary fixture never reaching the line), `CorrelationIdFilterTest` (5 — traceId-derived, fresh-UUID fallback, blank-traceId fallback, `finally` cleanup on exception, no overwrite of a stale id), `GlobalExceptionHandlerTest` (5 — correlation-id response header), JUnit XML fresh this run; `OtlpTracingExportTest` / `PrometheusMetricsEndpointTest` / `SecretRedactingValueMaskerTest` unchanged and green. **Docs.** [`docs/devlog/sprint-13-observability.md`](docs/devlog/sprint-13-observability.md) (new S13-09 section + contents line); [`docs/observability/standards.md`](docs/observability/standards.md) (the pinned log-line contract); `CHANGELOG.md` (this entry). — [detailed](docs/devlog/sprint-13-observability.md#s13-09-standardized-json-logs)

- **The MCP outbound destination policy — the SSRF guard (`S11-10`).** The MCP adapter opens a socket to a host the operator allowlisted, but an allowlisted *host* is not an allowlisted *destination*: a workflow step, a document, or a server response must never turn reachability into a call to a loopback, metadata, or private endpoint. - **The document lifecycle (S10-01): [`docs/architecture/document-lifecycle.md`](docs/architecture/document-lifecycle.md)** — the `documents.status` state machine of `knowledgebase`, as a diagram and a guarded transition table (the document-layer mirror of the run state machine, `S05-01`). The lifecycle is `UPLOADED → QUEUED → PROCESSING → INDEXED`, with `FAILED`, `DELETE_REQUESTED`, `DELETED`: `UPLOADED` (object stored + metadata row committed; the upload API returns `202`), `QUEUED` (the `ingestion-requested` event is enqueued via the outbox, awaiting a worker), `PROCESSING` (an `ingestion` worker holds the lease and is extracting → chunking → embedding → indexing), `INDEXED` (all chunks indexed — pgvector + FTS), `FAILED` (permanent failure or an exhausted retry budget), `DELETE_REQUESTED` (deletion requested; the lease is drained) and `DELETED` (object + chunks removed).
